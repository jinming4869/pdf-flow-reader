# v4「希声」工程回顾

本文回顾 v4 从文本结构、朗读运行时到六档策略和发布工程的主要演进。

## 背景

v4 的目标是在现有 PDF 连续阅读体验中加入本地朗读，同时保持以下边界：

- PDF 与朗读文字默认不离开本机
- 原生文字优先，扫描页按需 OCR
- 朗读行为与六档阅读速度协调
- 模型推理不得阻塞 PDF 读取和渲染
- 跳页、暂停和换文档必须可靠取消旧内容

## 第一阶段：统一文本结构

PDF.js 与 Tesseract.js 输出的坐标、段落和置信度格式不同。实现引入统一结构：

```text
TextSegment
→ ReadableChunk
→ 句子与自然段结构
→ 阅读策略选择
```

主要处理包括：

- PDF 坐标与页面坐标归一化
- 双栏阅读顺序
- 页眉、页脚、脚注、表格和公式降权
- 中文、英文和日文句界
- 原生文字与 OCR 来源质量评估

原生文字质量足够时直接使用；缺失、过少或结构不稳定时，才调度当前页附近的 OCR。OCR 的速度估算资格与朗读资格分别判断。

## 第二阶段：朗读运行时隔离

早期原型将模型推理与 PDF 本地服务放在同一进程中。CPU 密集推理可能延迟 Range 请求、心跳和页面响应，因此最终结构改为：

```text
renderer
→ local reader server
→ runtime router
→ child worker
→ ONNX runtime
```

运行时提供：

- 单并发推理与有限队列
- 请求 id 与 generation 隔离
- 超时和崩溃恢复
- 用户取消后的 worker 终止与重建
- 中英、日英片段路由与 PCM 拼接

## 第三阶段：六档策略

朗读状态从独立模式选择收敛为一个总开关与六档派生策略。每档策略明确：

- 是否自动朗读
- 是否显示阅读线
- 触发事件
- 内容过滤规则
- 语速与预取方式
- 取消和去重边界

六档分别承担连续随读、动态跟速、阅读线单句触发、段首句接力和最高两档点句等行为。策略本身尽量保持纯函数，应用层只负责提供页面、滚动和文字上下文。

## 第四阶段：跨页与取消

跨页连续朗读需要区分普通前进与上下文失效：

- 相邻向前翻页可以复用仍然有效的预生成结果
- 反向移动、远跳、换文档和文字来源变化使旧结果失效
- 点句采用最后一次请求优先
- 音频解码、scheduler、fetch 和 worker 推理使用同一取消边界

扫描页连续阅读还会沿阅读方向补充 OCR，避免固定附近页窗口耗尽后失去文本。

## 第五阶段：发布运行时

正式桌面包携带：

- 英文 q8 模型
- 中文、日文 v1.0 int8 模型与声音
- 中文、日文文本前端
- 自包含 CJK worker
- Tesseract.js 与四语 OCR 数据

构建脚本校验模型文件大小和 SHA-256；GitHub Actions 在目标平台原生构建 worker，并在打包后运行离线冒烟测试。

## 验证范围

自动化覆盖：

- 文本清洗、句界、双栏与段落模型
- OCR 调度、来源状态与质量门槛
- 六档策略、预取、点句和播放锁
- Range 读取、渲染调度与缓存
- worker 超时、取消、崩溃和背压
- 打包资源与离线模型发现

人工验证覆盖文字型、双栏与扫描 PDF 的滚动、OCR、跨页朗读、混排路由和用户干预。测试材料不进入公开仓库。

## 已知边界

- OCR 和 TTS 仍会受到模型精度影响。
- 浏览器自动化难以完整复现所有原生文字选择手势。
- 平台签名、公证和安装包体积仍有继续改善空间。

更具体的当前能力见 [`README.md`](../README.md)，版本变化见 [`CHANGELOG.md`](../CHANGELOG.md)。
