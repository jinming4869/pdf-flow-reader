# 决策记录

## 2026-07-31：保留英文链，新增共享中日文链

不把所有语言迁到 Python。英文继续使用已稳定的 `kokoro-js` worker；中文和日文共用一个 v1.0 int8 Python worker。这样缩小回归面，并让两种 CJK 语言共用约 115 MiB 的模型资源。

## 2026-07-31：语言提示与文字脚本共同路由

PDF 文本层当前只提供 `latin`、`cjk`、`mixed`，不能单靠提示区分中日文。路由器优先识别假名为日文；有汉字而无假名时使用中文；纯拉丁文字进入英文链。显式 `ja` / `zh` 提示仍被尊重。

## 2026-07-31：模型结果通过 NDJSON + WAV base64 返回

Python worker 每次只处理一个短朗读单元，WAV 通常小于数 MiB。用 stdout NDJSON 返回 base64 可避免临时音频文件、残留清理与路径竞态；父进程解码后沿用现有 Buffer 契约。若未来朗读单元显著增长，再升级为长度前缀二进制协议。

## 2026-07-31：发布资源边界不伪装成已完成

正式源代码会包含资源发现规则与清晰错误，但本阶段只接入本机 PoC 虚拟环境和模型。发布前仍需决定内置 runtime 或首次下载，并解决 `phonemizer-fork` / eSpeak 相关许可证合规；不会把开发机 `.venv` 直接打包。

## 2026-07-31：eSpeak 临时目录由父进程持有

硬取消使用 `SIGKILL`，Python 没有机会执行 `finally`。因此 ASCII eSpeak shadow 目录由 Node 父进程用 `mkdtemp` 精确创建、通过环境变量交给 worker，并在 kill / exit 时同步删除。真实取消与退出测试后没有新增残留目录。
