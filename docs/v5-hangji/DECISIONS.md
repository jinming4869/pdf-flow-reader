# v5「航迹」决定

## D1：版本主题词为「航迹」

- v3「回音」代表速度、视觉和声音对阅读节奏的回应。
- v4「希声」代表退到阅读身旁的本地 TTS。
- v5「航迹」代表书页、情绪与回读共同留下的阅读路径。

## D2：v5 是情感引擎，不是通用笔记系统

思维动作属于情感体验的一部分。产品目标是维持心流、提供适度挑战、重新解释唤醒，并把被触动的时刻变成可回看的痕迹。

## D3：使用自由套索与“丝带环＋墨线轨迹”

不使用矩形截图框作为主交互。套索图标采用丝带环意象，绘制轨迹具有圆润、柔软和轻微粗细变化，不呈现 Photoshop 式虚线选择框。

## D4：情绪使用连续二维坐标

横轴为负面到正面效价，纵轴为低到高唤醒。用户亲自落点；分类词只解释坐标，不替代连续值，也不由 AI 自动判断。

## D5：套索先保存，再生成

截图、文字来源、情绪与上下文首先本地落盘。一句复述异步补充；AI 失败只产生“等待回声”的状态，不产生数据丢失或回流阻塞。

## D6：回流由用户主动触发

套索界面只保留一句复述、情绪坐标与“回到书流”。短暂中断使用约 30 秒入流曲线，新书或长暂停使用约 90 秒曲线。

## D7：入流只提高当前档位内速度

目标位于当前档位偏高但仍有安全余量的区域，不跨档。手动滚动、调速或暂停拥有最高优先级并立即取消自动入流。

## D8：两类 AI 使用不同契约

- `TraceEchoProvider`：短文本、高频、目标 1–3 秒、可失败、允许稍后补生成。
- `BookAnalysisProvider`：长上下文、低频、质量优先、用户从书架显式触发、允许模型选择和更长等待。

第一版从一个 OpenAI-compatible provider 开始，后续再扩展具体供应商；产品代码不绑定 Zotero GPT 的模型设置。

## D9：在线大模型是正式但可选的 v5 能力

阅读本体、本地截图、情绪坐标和回流不依赖网络。全文分析在线优先且由用户主动触发。一句复述可以选择本地小模型或在线快速模型，但任何实现都不能成为保存门槛。

## D10：凭据与 Zotero 解耦

API 密钥由「夜晚的书斋」单独配置，存入 macOS Keychain 或 Windows Credential Manager。Prompt 可以继承，Zotero `prefs.js` 和其中的凭据不得被读取或复制。

## D11：本地记录是事实源，外部工具是目的地

每本书只需设置一次归档去向。Zotero 是 Prompt 来源之一和成果归档目的地之一；Obsidian 与专用文件夹是并列适配器，不是并行事实数据库。

## D12：复杂 Prompt 留在书架

流动阅读期间只出现一句复述。分析、全文总结和 LSE Reading Worksheet 位于单本书菜单；融贯只在多书上下文出现。笔记续写、提升写作等不进入 v5 核心流程。

## 2026-08-09 冻结决定

### D13：v5 按小版本线性交付

v5.0 只交付离线核心；v5.1 交付图文回声与基础归档；v5.2 交付 Zotero 和单书分析；v5.3 交付多书融贯。

### D14：v4.1 书架先成为独立基线

从远端 `main` 干净移植书架轮播与开书动画，独立验收后再建立 v5.0 分支。

### D15：Electron 桌面版提供完整能力

普通浏览器模式保持基础阅读和开发调试，不为追求浏览器对等扩大 v5 文件、凭据和归档范围。

### D16：痕迹使用可检查文件目录

用户事实、裁图、AI 和归档状态分层保存，采用原子文件操作，不引入 SQLite；现有 localStorage 只保留普通偏好与阅读位置。

### D17：允许不完整草稿

套索闭合即保存；情绪未落点或裁图失败都不阻塞回流，书架提供补充、重试和删除。

### D18：文档内容身份与路径分离

移动、改名或复制的相同 PDF 保持同一航迹；内容变化的版本严格分书，原路径失效时由用户重新定位并验证。

### D19：保存可恢复裁图与原始路径

保存带少量上下文的矩形原图和归一化套索路径，遮罩与透明不规则图是可重新生成的派生产物。

### D20：回流只响应明确恢复动作

新书或长离开约 90 秒，短中断约 30 秒；任何手动操作立即取消且曲线不自动复活。

### D21：未配置 AI 时保持安静

离线核心完整可用，不催促配置；相关版本中的 AI 入口只显示可选状态。

### D22：第一阶段只做在线 OpenAI-compatible provider

快速回声模型和强分析模型分别配置；本地 LLM 留给独立 PoC，不阻塞 v5.1 或 v5.2。

### D23：一句复述默认使用套索裁图与文字

首次启用时一次性说明发送范围；不上传整页或完整 PDF。

### D24：分析语料按次选择

默认使用航迹语料；全文语料属于重型任务，扫描书全书 OCR 必须再次明确授权。

### D25：视觉能力不足时降级为纯文字

Provider 支持视觉时发送图文，不支持时自动使用文字并记录 `text-only`，不在每条痕迹上重复询问。

### D26：每本书只有一个主要归档目的地

更改目的地只影响新痕迹；重新导出全部必须由用户主动触发，旧目的地内容不被自动删除或改写。

### D27：Zotero 关联必须由用户确认

系统可以推荐候选，但关联、创建或导入均需明确选择，不能自动制造重复条目。

### D28：内置 Prompt 与用户 Prompt 分层

内置 Prompt 版本化且只读；用户复制或新建的 Prompt 独立保存，升级不覆盖，凭据不进入 Prompt 文件。

### D29：套索是显式、一次性的模式

通过丝带环或 `L` 进入；完成或取消后退出；取消不保存并保持暂停，普通拖动仍用于文字选择。

### D30：情绪使用连续二维平面

支持鼠标、键盘和屏幕阅读器；邻域词只解释坐标，不替代用户落点，也不设置默认中心值。

### D31：单书书架按“航迹／分析／归档”分区

各分区随小版本能力出现，不提前放置不可用空壳；航迹始终是默认入口。

### D32：保留最小修订历史与 30 天回收站

首次情绪不可变，修正保存当前值；删除先软删除，彻底清除需再次确认；本地修改只把外部归档标记为 stale。

### D33：正式平台保持 macOS Apple Silicon 与 Windows x64

当前实施先保证产品所有者本机 macOS 可运行，Windows 与 GitHub 公开发布适配后置到独立阶段。

### D34：凭据安全失败时禁用 AI

系统安全存储不可用时不退回明文 localStorage、硬编码密钥或无提示弱加密。

### D35：性能门槛由 PoC 证据产生

先锁定不阻塞回流、不抢控制、不泄漏内存等不变量，再在 8GB/16GB 目标设备上冻结 P50/P95 数值。

### D36：私人 PDF 只作本机验收

私人样本不提交 Git，不在日志中暴露内容、文件名或路径，也不默认发送给 AI。

### D37：诊断本地、默认关闭、无内容

只记录时延、状态、取消原因、内存和错误码；不记录正文、裁图、情绪、密钥或绝对路径，不上传遥测。

## 实施决定

### D38：核心 trace 文件不含 AI 与归档数据

`reading-trace.mjs` 只定义用户事实、裁图状态和情绪状态；echo 与 archive 由后续独立文件和状态机管理。

### D39：阶段 3 不复用旧元数据指纹

旧 `storage.mjs` 指纹基于文件名、大小和修改时间，不满足内容身份要求。ReadingTrace 接受外部提供的严格内容指纹；算法与迁移由阶段 4 解决。

### D40：readingOrder 是不可重编号的插入序号

删除中间痕迹后允许出现空洞；书架可以按 capturedAt 和 readingOrder 稳定排序，不能为视觉连续而重写已存在的引用。

### D41：Trace IPC 只接受本地 reader renderer

正式主进程拒绝非 `127.0.0.1` reader 来源；repository 不通过本地 HTTP 暴露，preload 也不暴露原始 ipcRenderer。

### D42：业务错误通过显式信封跨 contextBridge

主进程只返回稳定 code 与 message；preload 透传 plain object，renderer client 在主世界重建 Error，避免 Electron 丢失自定义 Error 属性。

### D43：readingOrder 可以有空洞，不能重复

Repository 以持久计数器和已有最大序号的较大者分配，并先推进计数器再写 trace；崩溃最多留下空洞，不会重复。

### D44：v5.0 内部裁图使用 PNG 与 4M 输出像素预算

本机高 DPR PoC 证明 4M 像素足以保持局部清晰并约束内存；repository 只接受有 PNG 签名、尺寸明确且不超过 64MB 的 crop。

### D45：保存矩形上下文原图，套索遮罩是派生表现

裁图事实源保留带 padding 的矩形区域与原始归一化路径；不规则透明图和路径外淡出可以重新生成，不覆盖原图。

### D46：裁图二进制写入服从 trace revision

saveCrop 在同文档锁内检查 expectedRevision，原子写入 crop.png 后更新 CROP_READY；迟到结果不能覆盖更新后的 trace。

### D47：正式套索交互由独立 controller 编排

app.mjs 只提供暂停、TTS 取消、页面 chunks/canvas、速度上下文和返回回调；状态机、pointer、墨线、几何、crop 与持久化都留在 `trace-capture-controller.mjs`。

### D48：正式 UI 只接受 PDF.js 内容 fingerprint

旧文件元数据指纹继续服务最近阅读，但不能锚定航迹。PDF.js fingerprint 缺失时关闭航迹入口，不静默降级。

### D49：取消套索退出一次性模式并保持暂停

L、Esc、右键、过短路径或跨页路径不创建 trace；解除视口冻结后播放状态仍为暂停，符合冻结需求 D29。

### D50：情绪事实只存连续坐标

邻域词、象限名称和 UI 文案都是可替换解释层，不进入 ReadingTrace；坐标保留三位小数并限制在 [-1, 1]。

### D51：crop 与 emotion 共用单 trace mutation queue

所有 revision 写入按最新 trace 串行；快速 pointer / keyboard 修改和异步 crop 不能互相覆盖。

### D52：首次情绪与修正值分离

PLACE_EMOTION 写入 original 与 current；REVISE_EMOTION 只更新 current。键盘和 pointer 使用同一事件契约。

### D53：回流目标取当前档位 0.82 上部位置

目标不低于用户当前速度，也不高于当前档位 max；已在目标之上时不制造减速或假曲线。

### D54：十分钟作为初始长暂停阈值

新书和应用恢复始终使用 90 秒；其他中断达到十分钟时使用 90 秒，否则使用 30 秒。阈值可由阶段 10 体验调整。

### D55：手动操作只取消入流，不强制暂停阅读

滚轮、触摸、键盘、调速等立即终止曲线；若用户没有按暂停，自动阅读回到其手动速度继续。
