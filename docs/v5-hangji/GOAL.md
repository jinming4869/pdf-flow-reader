# v5「航迹」目标

状态：需求已校准；实现未开始。

## 目标

在不把「夜晚的书斋」变成通用批注软件的前提下，为沉浸式 PDF 阅读建立完整的“触动—留痕—回流—回看”循环。

## 完成线

1. 用户可以用带丝带环意象的自由套索圈选同一 PDF 页内的任意区域；进入套索立即暂停自动滚动与 TTS，并保持当前视口。
2. 圈选完成后从高质量页面渲染结果生成清晰裁图，同时保存归一化套索路径、页码、PDF 指纹、速度档位、物理速度与时间。
3. 阅读痕迹先在本机原子落盘；断网、AI 未配置、超时或生成失败都不能丢失截图、文字、坐标或阻塞用户回流。
4. 用户在连续二维平面亲自选择效价与唤醒坐标；系统可以提供附近情绪词，但不得替用户推断或自动填写情绪。
5. 套索后的界面只保留一句复述、情绪坐标盘和一个“回到书流”主动作；复述尚未生成时也能立即回流。
6. 短暂中断后以约 30 秒曲线、新书或长时间暂停后以约 90 秒曲线，从当前速度逐渐进入当前档位偏高区域；不得自动跨档，任何手动滚动、调速或暂停立即取得控制权。
7. 每本 PDF 形成可点击的情绪航迹图，能够按阅读顺序、页码与二维坐标回看截图和一句复述，并跳回原书位置。
8. 本地记录是唯一事实源；用户可以为每本书选择 Zotero、Obsidian 或专用文件夹作为归档目的地，不需要每次套索重复选择。
9. 高频一句复述与低频全文分析使用不同 provider 契约；前者追求 1–3 秒且可失败，后者由用户从书架主动触发、允许等待并优先质量。
10. “分析”“全文总结”“LSE 阅读 Worksheet”只出现在书架；“融贯”只在多文献上下文出现。v5 阅读界面不暴露复杂 Prompt 菜单。
11. API 密钥由应用单独授权并使用操作系统凭据存储；不得读取 Zotero `prefs.js` 中的密钥。
12. 在普通文字 PDF、双栏论文、扫描书及大型 PDF 上完成真实验收，不使现有渲染、OCR、六档阅读和希声发生回退。

## 非目标

- 不复制 Acrobat 式高亮颜色、图章、绘图和批注工具箱。
- 不替用户自动判断阅读情绪。
- 不要求 AI 成功后才能保存或回流。
- 不把 Zotero 变成应用运行前提，也不复制其文献管理与同步系统。
- 不在第一版实现跨设备实时同步、协作批注或 PDF 内容编辑。
- 不在流动阅读界面提供全文分析、续写、提升写作或模型选择面板。
