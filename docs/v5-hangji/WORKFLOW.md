冻结需求：[`REQUIREMENTS.md`](./REQUIREMENTS.md)

## 1. 单线程规则

同一时刻只允许一个工程阶段处于进行中。即使后续模块技术上可以并行，也必须先通过前一阶段的退出门。

每个阶段固定执行：

```text
确认本阶段契约
→ 先写失败测试
→ 实现最小能力
→ 运行局部测试
→ 运行完整回归
→ 更新决定、风险和复核记录
→ 建立本地检查点提交
→ 输出阶段报告
→ 通过退出门后进入下一阶段
```

不得用后续功能掩盖当前阶段的失败；不得在一个提交中混入无关重构。

## 2. 分支与工作树纪律

- 不在含有未提交私人研究材料的工作树中开发。
- v4.1 从远端 `main` 的干净提交建立独立工作树。
- v5.0 从已验收的 v4.1 基线建立新分支。
- v5.1、v5.2、v5.3 分别从前一已验收版本继续。
- 私人 PDF、测试输出、密钥、绝对路径和本机诊断不得进入 Git。
- 本地检查点提交不等于授权推送；GitHub push、PR、merge 与 release 均需单独确认。

## 6. 停止条件

出现下列任一情况时必须停止推进：

- PoC 证明冻结行为不可行；
- 发生用户数据丢失或不可恢复损坏；
- 需要降低凭据安全等级；
- 需要上传未获授权的 PDF、裁图或正文；
- 需要修改外部 Zotero、Obsidian 或 GitHub 状态；
- 当前阶段完整回归未通过；
- 下一步会覆盖非本任务产生的未提交文件。
