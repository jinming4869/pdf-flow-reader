# v5.2「回望」需求草案

状态：**草案，等待产品所有者确认**（2026-08-16）

基线：v5.1 验收基线（`b47608e`）

本文件从 v5.0 已冻结 REQUIREMENTS 第 6 节与 v5.1 冻结需求展开，不改动已冻结范围。发布策略不变：全系列完成后统一发布。

## 1. 版本目标

v5.2 交付：

1. 发送前逐项授权机制（补 v5.1 遗留 V1-R6 的“逐项授权”）；
2. Zotero 归档；
3. 单书分析（`BookAnalysisProvider`）；
4. 全文总结；
5. LSE Reading Worksheet；
6. 复杂 Prompt（分析 / 总结 / LSE）进入分层体系。

北极星不变：本地记录是唯一事实源；AI 输出与用户事实分离；重型能力只出现在书架。

## 2. 发送前逐项授权

- 三种发送范围：一句复述（圈选文字 + 裁图）、单书分析（整书航迹聚合）、全文总结（整书正文）。
- 范围从小到大；每次升级范围都需要明确确认，禁止静默扩大。
- 授权状态按书保存；“配置即授权”不再适用于分析级范围。
- 每次发送前在界面列出发送内容清单（多少字、多少张图、是否含正文）。
- 诊断与日志依旧不落任何发送内容。

## 3. Zotero 归档

技术事实（2026-08-16 查证）：

- Zotero 7/8 local API（`http://127.0.0.1:23119/api/`）本地**只读**，无需认证；Zotero 10+ 提供运行时授权的本地写入，Zotero 7/8 没有；
- 写入条目必须走 zotero.org Web API（需要用户自建 API key 与 library ID）或 connector 端点（parentItem 会被静默忽略，不可用）。

据此设计：

- Zotero 是第三种目的地类型，与文件夹 / Obsidian 并列。
- 本地匹配：通过 local API 只读查询，把当前书与 Zotero 条目匹配（优先 PDF 附件文件名校验，其次标题）。
- 写入：用 Web API 在匹配条目下创建 child note（一句话复述 + 情绪坐标 + 页码锚点 + 本地归档路径引用）；裁图不上传 Zotero。
- Zotero API key 与 library ID 存 safeStorage（`zotero` 槽位），不读 prefs.js，不读 zotero.sqlite。
- Zotero 未安装 / 未开启 local API / 无匹配条目 / 无网络：全部是安静失败，不阻塞任何本地功能。
- 不做双向同步、不创建条目、不修改条目元数据、不动 Zotero 附件。

## 4. 单书分析

- 输入：一本书的本地航迹聚合（情绪坐标序列、阅读顺序、档位变化、时间分布）+ 圈选文字集合。
- 输出：阅读轨迹概览（结构、节奏、情绪流动、反复回到的位置）。
- 只在书架单书详情触发，流动阅读中不出现。
- 使用 `echo-strong` 凭据槽位，与快速回声分离。

## 5. 全文总结

- 输入：明确授权后发送整书正文（或按章分块，先处理本地可用文本，扫描 PDF 用 OCR 文本）。
- 输出：结构式总结（分节，保留页码锚点）。
- 长书分块处理，进度可见，可取消；失败不阻塞。
- 总结保存在本地记录，AI 输出与用户痕迹分列。

## 6. LSE Reading Worksheet

- 按 LSE 批判阅读工作纸的结构生成：作者主张、证据类型、论证结构、方法局限、与既有文献的关系、未回答的问题。
- 输入：单书分析结果 + 授权后的正文（可降级为圈选文字集合）。
- 输出为可归档的 Markdown。

## 7. Prompt 分层扩展

- 新增内置只读 Prompt：`analysis`、`summary`、`lse`（各带版本号）。
- 用户副本、升级不覆盖、不含密钥，规则与 v5.1 `echo` 完全一致。

## 8. 非目标（仍属后续版本）

- v5.3 多书选择与融贯分析。
- 双向同步、条目创建、Zotero 文献库管理。
- 跨设备同步、协作批注。

## 9. 验收门（阶段 16）

- 逐项授权：三种范围都能在界面确认清单后发送；拒绝发送时一切本地功能完好。
- Zotero：真实 Zotero 7 环境实测匹配 + Web API 写入 child note；四种安静失败路径全部验证。
- 单书分析、全文总结、LSE：真实书实测，输出结构与锚点正确；失败不阻塞。
- Node 完整回归、Electron smoke、packaged 实测（凭据、授权、分析、Zotero 降级）。
- 诊断默认关闭且完全本地。
