# v5.2「回望」冻结需求

状态：**已冻结，等待线性实施**（2026-08-16）

基线：v5.1 验收基线（`b47608e`）

本文件从 v5.0 已冻结 REQUIREMENTS 第 6 节与 v5.1 冻结需求展开，不改动已冻结范围。发布策略不变：全系列完成后统一发布。

产品所有者决策（2026-08-16）：

1. Zotero 写入接受 Web API；同时要求双向连接：Zotero 中可直接用书斋打开 PDF，书斋中打开的 PDF 可导入 Zotero；
2. 全文总结输入为整书正文；
3. 单书分析与全文总结合并为一次授权、一次生成；
4. LSE 工作纸按官方模板原样。

## 1. 版本目标

v5.2 交付：

1. 发送前逐项授权机制（补 v5.1 遗留 V1-R6 的“逐项授权”）；
2. Zotero 双向连接；
3. 单书回望（分析 + 全文总结合并）；
4. LSE Reading Worksheet；
5. 复杂 Prompt（回望 / LSE）进入分层体系。

北极星不变：本地记录是唯一事实源；AI 输出与用户事实分离；重型能力只出现在书架。

## 2. 发送前逐项授权

- 三种发送范围：一句复述（圈选文字 + 裁图）、单书回望（整书航迹聚合 + 整书正文）、LSE 工作纸（回望结果 + 整书正文）。
- 范围从小到大；每次升级范围都需要明确确认，禁止静默扩大。
- 授权状态按书保存；“配置即授权”不再适用于分析级范围。
- 每次发送前在界面列出发送内容清单（多少字、多少张图、是否含正文）。
- 诊断与日志依旧不落任何发送内容。

## 3. Zotero 双向连接

技术事实（2026-08-16 查证）：

- Zotero 7/8 local API（`http://127.0.0.1:23119/api/`）本地**只读**，无需认证；Zotero 10+ 提供运行时授权的本地写入，Zotero 7/8 没有；
- 写入条目必须走 zotero.org Web API（需要用户自建 API key 与 library ID）或 connector 端点（parentItem 会被静默忽略，不可用）。

### 3.1 Zotero → 书斋

- macOS 上注册 PDF 文件关联：Zotero 附件可用“打开方式”选中书斋，双击 PDF 直接进入阅读。
- 复用已有 open-file 处理；不接管其他格式。

### 3.2 书斋 → Zotero

- 通过 local API 只读匹配当前书：PDF 附件文件名校验优先，其次标题；
- 已匹配：Web API 在条目下写 child note（一句复述 + 情绪坐标 + 页码锚点 + 本地归档路径引用）；
- 未匹配：Web API 创建条目（PDF 类型）→ 上传 PDF 附件 → 写第一条 child note；
- 裁图不上传 Zotero；Zotero API key 与 library ID 存 safeStorage（`zotero` 槽位），不读 prefs.js、不读 zotero.sqlite；
- Zotero 未安装 / 未开 local API / 无网络：安静失败，不阻塞任何本地功能；
- 不修改条目元数据、不动 Zotero 已有附件、不做双向同步。

## 4. 单书回望（分析与全文总结合并）

产品决策：合并为一次授权、一次生成。

- 输入：一本书的本地航迹聚合（情绪坐标序列、阅读顺序、档位变化、时间分布）+ 圈选文字集合 + 授权后的整书正文。
- 输出：单书回望 = 阅读轨迹概览（结构、节奏、情绪流动、反复回到的位置）+ 结构式总结（分节，保留页码锚点）。
- 长书按章分块渐进生成，进度可见，可取消；失败保留已完成部分。
- 只在书架单书详情触发；使用 `echo-strong` 凭据槽位；输出保存在本地记录，AI 输出与用户痕迹分列。

## 5. LSE Reading Worksheet

- 按 LSE 官方模板字段原样生成：作者主张、证据类型、论证结构、方法局限、与既有文献的关系、未回答的问题。
- 输入：单书回望结果 + 授权后的正文（可降级为圈选文字集合）。
- 输出为可归档的 Markdown，界面标注模板版本与来源。
- 独立触发（不与回望合并）。

## 6. Prompt 分层扩展

- 新增内置只读 Prompt：`review`（单书回望）、`lse`（各带版本号）。
- 用户副本、升级不覆盖、不含密钥，规则与 v5.1 `echo` 完全一致。
